## Паспорт рецепта развёртки (зафиксирован машинно)

| поле | значение |
|---|---|
| набор нулей | Odlyzko Zeta Tables, файл `zeros1`, ~9 знаков |
| файл | `data/zeta/zeros_odlyzko_100k.txt`, sha256 `3436c916a7878261ac183fd7b9448c9a4736b8bbccf1356874a6ce1788541632` |
| диапазон индексов | нули 1…100 000, γ от `14,134725142` до `74920,827498994`; 99 999 зазоров |
| формула θ | `θ(t) = Im logΓ(1/4 + i t/2) − (t/2)·ln π`, без обрезания ряда |
| точная развёртка | `s_i = (θ(γ_{i+1}) − θ(γ_i))/π` |
| развёртка корпуса | `s_i = (γ_{i+1} − γ_i)·ln(γ_i/2π)/(2π)` — ведущий член, множитель по НИЖНЕМУ нулю |
| исключение краёв | края НЕ исключаются: используются все 99 999 зазоров |
| оценка разброса | выборочная std с `ddof=1`; перцентили — линейная интерполяция |
| коммит корпуса | `04430c0dc154ed3ec987704fe9b74bbcb40a3e9b` |

Контроли паспорта: θ восстанавливает номер нуля `N = 99 999,405` против
100 000; среднее развёрнутых зазоров равно `1,000000` (θ) и `0,999986`
(ведущий член).

## Что ДОКАЗАНО

**1. Число 0,42201569295012265 — это std surmise Вигнера, а не точного закона
GUE.** Оно равно `sqrt(3π/8 − 1)` и воспроизведено четырьмя независимыми
путями:

| путь | значение | отличие от цели |
|---|---|---|
| A — замкнутая форма | `0,4220156929501229` | `5,6e-17` |
| B — mpmath, 50 знаков, квадратура по плотности | `0,422015692950123` | согласуется с A |
| C — Гаусс–Лежандр по функции ВЫЖИВАНИЯ, `E[s²]=∫2s(1−F)ds` (иной объект — CDF) | `0,42201569293918684` | `1,09e-11` |
| D — Монте-Карло 4·10⁶ по обратной CDF, seed 20260815 | `0,4220255909610701` ± `1,49e-4` | `|Δ| = 9,9e-6 < 4·SE` |

Точный закон зазоров GUE даёт `0,424258`, то есть колонка корпуса «GUE
(computed)» отличается от точного закона на `+0,531 %`.

**2. Корпусное 0,4009 — настоящее измерение из сырых нулей, а не артефакт
рецепта.** Пятнадцать законных вариантов рецепта (`ddof=0/1`, ренормировка на
выборочное среднее, множитель по нижнему/верхнему/среднему нулю, точная
θ-развёртка, обрезание 1/10/100/1000 зазоров с краёв, объединённая
внутрикорзинная std по 10 высотным корзинам, среднее корзинных std) дают
значения в диапазоне `0,400924…0,401127`, то есть от `+0,006 %` до `+0,057 %`
относительно напечатанного `0,4009`. Одиннадцать из пятнадцати воспроизводят
напечатанное число в пределах `5e-5`. Версии «иная нормировка», «иная выборка»
и «ошибка корпуса» этим отвергнуты: результат устойчив к выбору развёртки.

**3. Кейс `cases/zeta_unfolding_std_recipe_20260815.py`: вердикт сита — ПОДТВЕРЖДЕНО на CPython 3.14.3 в области охвата для класса воспроизведения измеренной статистики из сырых данных.**
Три пути к числу принципиально разные: эталон — θ-развёртка на
scipy `loggamma` и numpy (`0,4009327315`); наблюдение — развёртка корпуса на
ЧИСТОМ Python со своим парсером файла и `math.fsum` (`0,4009263778`); второй
эталон — та же θ-развёртка на mpmath при 30 знаках со накоплением моментов в
Python. Сита: С2 `−0,01 %` при выведенной из печатной точности терпимости
`1,247e-4`; С3 `−0,00 %`; С4 подставка `0,4220156929501` отклонена (`+5,26 %`);
С5 пуассоновский контроль через тот же конвейер даёт `1,0148` и отвергнут
(`+153 %`); С10 `z = +0,0` (полуширина `0,46 %`); С12 согласие со вторым
методом в пределах измеренного разброса; С13 все 12 пропусков объявлены; С14
сквозная подставка получила ОПРОВЕРГНУТО.
Отпечаток рецепта `ca42e009adaca3bf`, паспорт цели `9e1b6776d16762e6`,
sha16 входов `3436c916a7878261`.

**4. Отклонение, о котором сообщает корпус, посчитано относительно surmise.**
`0,4009327315 / 0,4220156930 − 1 = −5,00 %` — совпадает с напечатанным
`−5,00 %`. Относительно ТОЧНОГО закона GUE то же измерение даёт `−5,50 %`,
то есть выбранный корпусом эталон занижает собственное отклонение корпуса.

## Что НЕ доказано

- НЕ доказано согласие измерения с теорией случайных матриц: отклонение
  `−5,50 %` от точного закона GUE остаётся ОТКРЫТЫМ. Чистое масштабирование
  `s → αs` его не объясняет (std `−5,50 %` против p95 `−2,17 %` и p50
  `+0,29 %`), нужен член, меняющий ФОРМУ распределения; поправка конечной
  высоты (Bogomolny–Bohigas–Leboeuf–Monastra 2006, рычаг `1/L` ≈ 0,153…0,107)
  не оценена количественно.
- Пункт 2 приказа (перплексия `1,87` против `2,2402780777` из train loss
  `0,8066`) в этом тике НЕ выполнялся: вердикт «ошибка числа» пока не проверен
  на сопоставимость шкалы, токенизации, усреднения и стадии обучения.
- Пункты 3–5 приказа (SLA ОС-матрицы, чанкинг разведки корпуса, кодовый бюджет
  новизны) в этом тике реализованы только как правила текста крона, но НЕ как
  шаги гейта.
- НЕ доказана работа на macOS и Windows: обе ОС остаются `not-evaluated`,
  SLA приказа (после двух подряд `not-evaluated` → `platform-unverified`)
  применяется со следующего тика. CPython 3.12.13 в песочнице без `numpy` и
  `pyyaml` — полный каскад там не прогонялся, пропуск объявлен причиной.
- Статус инструмента: стабилен на Linux/CPython, выявляет реальные
  несоответствия в корпусе и поддерживает воспроизводимый регресс;
  межплатформенная верификация пока неполна. Проверено на указанных версиях
  CPython (3.14.3), а не платформонезависимо.
