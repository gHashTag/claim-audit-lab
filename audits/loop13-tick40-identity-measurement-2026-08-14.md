# Тик 40: измерение детектора тождественности, мутационная валидация и baseline-гейт

Дата: 14 августа 2026. Инструмент: золотое сито, рабочая копия

3.14.4, 3.12.13.

## Контракт тика

- **Цель**: выполнить семь пунктов приказа — baseline, reason-code, расширение
  положительного корпуса, негативный стресс-корпус, матрица интерпретаторов,
  мутационная проверка, CI-гейт.
- **Входы**: детектор `goldsieve/identity.py` + `goldsieve/identity_deep.py`,
  реестр `claims.yaml` (100 записей), корпус Trinity (HEAD `04430c0`).
- **Ожидаемый артефакт**: измеренные метрики детектора, мутационный тест,
  неизменяемый baseline, гейт с подставками, отчёт.
- **Критерии приёмки**: ноль ложных срабатываний на реальных кейсах; каждая
  внесённая поломка обнаружена; гейт закрывается на подставке.

## Главная находка: заявление тика 39 не подтверждается

Тик 39 доложил, что покрытие конструкций `globals`, `functools.partial` и
`lambda` подтверждено вердиктами ПОДТВЕРЖДЕНО. **Это заявление неверно.**
ПОДТВЕРЖДЕНО там означало лишь, что детектор промолчал, а молчание детектора и
покрытие класса конструкций — разные вещи. Измерение на специально построенном
корпусе фикстур дало:

| класс конструкции | поймано до ремонта |
|---|---|
| прямые формы | 3/3 |
| closure | 1/3 |
| decorator | 1/3 |
| bound method | 0/3 |
| callable object | 0/3 |
| default arg | 0/3 |
| globals | 0/3 |
| lambda | 0/3 |
| partial | 0/3 |

**Чувствительность 0,1852 [5/27]**. То есть три из шести классов, объявленных
закрытыми в тике 39, детектор не видел вовсе. Причина: разбор шёл по имени
функции (`__name__`), а у lambda, `partial` и вызываемого объекта этого атрибута
либо нет, либо он бесполезен, и код молча возвращал «не производно» — тот же
вид тихого отказа, что был найден в лупе 12, только в другом месте.

## Что сделано

### 1. Корпус фикстур (28 положительных, 16 негативных)

`goldsieve/identity_corpus.py`: 28 подтверждённых семантических вырождений в
десяти классах (closures, default arguments, bound methods, decorators,
callable objects, nested partial, изменение глобального окружения, захват самой
функции эталона, прямые формы) и 16 негативных стресс-ловушек: эквивалентные
функции с разным AST, альфа-переименование, перестановка независимых операций,
одинаковые захваченные значения при разных идентификаторах объектов,
сериализация состояния вызываемого объекта, честные аналоги каждой позитивной
формы. Фикстуры грузятся настоящим `module_from_spec` **без** регистрации в
`sys.modules` — ровно так, как CLI грузит реальные кейсы.

### 2. Ремонт детектора: `goldsieve/identity_deep.py`

Разбор происхождения ЗНАЧЕНИЯ, а не совпадения имён: поиск узла AST по
`co_firstlineno` (работает для lambda), объемлющие функции, ячейки замыкания,
значения по умолчанию, поля экземпляра из `__init__`, `functools.partial`
любой вложенности, `__wrapped__`, загрязнённые глобальные контейнеры и
функции-наполнители этих контейнеров. Принцип сохранён: **неизвестный источник
СНИМАЕТ подозрение** — сито не имеет права записывать в вырождение то, чего не
разобрало.

Результат после ремонта, воспроизведён на трёх интерпретаторах:

| метрика | значение |
|---|---|
| чувствительность | **1,0000 [28/28]** |
| специфичность на стресс-корпусе | **1,0000 [16/16]** |
| ложные срабатывания на 48 реальных кейсах | **0** (специфичность 1,0000 [44/44]) |
| самопроверка каскада | 156 пройдено, 0 провалено |
| перепрогон реестра | 97 совпало, **0 изменилось ситом**, 3 изменилось из-за корпуса, 0 не сопоставлено |

Ноль переворотов ситом — усиление детектора не переписало ни одного прежнего
вердикта. Это существеннее, чем если бы перевороты были: значит усиление не
подгонялось под желаемый результат.

### 3. Мутационная проверка (`mutation_identity.py`)

Корпус фикстур сам по себе ничего не доказывает: он мог бы проходить и при
сломанном детекторе. Поэтому в детектор вносятся восемь поломок (текст
`identity_deep.py` не правится — мутант грузится и подставляется в
`sys.modules`), и от корпуса требуется поймать каждую.

| поломка | обнаружена | как проявилась |
|---|---|---|
| извлечение глобального состояния | да | 2 пропуска |
| наполнители глобального состояния | да | 1 пропуск |
| нормализация `functools.partial` | да | 3 пропуска |
| разбор lambda | да | 3 пропуска |
| приёмник связанного объекта (`self`/`cls`) | да | 6 пропусков |
| значение по умолчанию от эталона | да | 1 пропуск |
| чтение захваченной ячейки | да (после ремонта корпуса) | 1 пропуск |
| разбор поля объекта | да | 1 пропуск |

**Мутационная проверка нашла дефект в самом корпусе**: поломка чтения
захваченной ячейки (`_closure_value`) сначала не давала ни одного пропуска —
значит этот путь корпусом не проверялся по существу, а замыкания ловились
другим путём. Добавлена фикстура, где эталон захвачен как ФУНКЦИЯ
(`_make(_reference)` возвращает `lambda: fn()`), и парная негативная с
`_read_own`. После этого 8/8.

### 6. CI-гейт (`ci_gate.sh`) и его подставки

Гейт прогоняет по матрице интерпретаторов самопроверку каскада, корпус фикстур,
мутационную проверку, калибровку на реестре и сверку с baseline. Блокирует
слияние при пропуске вырождения, ложном срабатывании, необнаруженной поломке,
ухудшении метрики или неклассифицированном отклонении.

Гейт проверен ПОДСТАВКАМИ — иначе он был бы проверкой, которая прошла бы и на
сломанном инструменте:

- поломка `_tainted_writers` в рабочем файле → «ГЕЙТ ЗАКРЫТ: 3 причин»,
  в том числе «метрика ухудшилась: sensitivity 1.0000 → 0.9643»;
- подмена одного вердикта в baseline без записи в `reasons.yaml` → «вердикт
  изменился без reason-code», неклассифицированных отклонений 1, гейт закрыт.

Оба файла после проверок восстановлены; отпечаток `identity_deep.py` сверен.

## Что ДОКАЗАНО

1. Заявление тика 39 о покрытии `globals`/`partial`/`lambda` неверно:
   измеренная чувствительность до ремонта — 0,1852 [5/27], три класса ловились
   в 0 случаях из 3.
2. После ремонта детектор ловит все 28 подтверждённых вырождений и не даёт ни
   одного срабатывания на 16 негативных ловушках и 44 честных реальных кейсах.
3. Каждая из восьми внесённых поломок обнаруживается корпусом; до добавления
   фикстуры с захватом функции одна поломка не обнаруживалась — этот пробел
   найден мутационной проверкой, а не рассуждением.
4. Метрики разбора конструкций одинаковы на CPython 3.12 и 3.14.
5. Усиление детектора не изменило ни одного вердикта реестра: 97 совпало,
   0 изменилось ситом.
6. Гейт закрывается на обеих подставках, то есть отличает исправное состояние
   от сломанного.

## Что НЕ доказано

1. Полнота классов конструкций. Десять классов и 28 фикстур — не весь язык
   Python. Не покрыты: дескрипторы и `property`, метаклассы, `__getattr__`,
   динамический `exec`/`eval`, `functools.lru_cache`, генераторы и корутины,
   C-расширения, многопоточная передача через `contextvars`.
2. Верхняя граница доли ложных срабатываний. Наблюдение «0 из 60» (44 реальных
   + 16 негативных) по правилу трёх даёт верхнюю оценку около **5 %** при 95 %
   доверии, а не ноль.
3. Отсутствие ложных срабатываний ОСТАЛЬНЫХ сит: калибровка построена только
   для детектора тождественности. Остаётся OPEN.
4. Независимость от платформы: все прогоны на одной ОС (Linux x86_64); другая
   ОС не проверялась.
5. Пригодность 3.12 как полноценной ветки матрицы: там прогнан только разбор
   конструкций, каскад и калибровка пропущены из-за отсутствия numpy и pyyaml.
6. Утверждение «детектор не пропускает вырождений в реальном реестре». Доказано
   лишь, что на 48 текущих кейсах пропусков нет при разметке независимым
   текстовым разбором; разметка сама может быть неполна — в лупе 12 она была
   неверна дважды.
