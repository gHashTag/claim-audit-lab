# Trinity Math Cloud — спека сервиса (черновик 1, 2026-08-14)

Статус: черновик архитектуры. Ни одна из частей ещё не реализована. Документ
описывает контракты, а не достигнутое состояние.

## 0. Что в присланном черновике надо поправить до кода

1. **Локальные данные доступны.** Утверждение «репозиториев нет в workspace»
   неверно для песочницы этой сессии: корпус лежит в
   `/home/user/workspace/corpus/trinity` (коммит `04430c0`), нули Одлыжко —
   `data/zeta/zeros_odlyzko_100k.txt` (sha16 `3436c916a7878261`). Спека должна
   ссылаться на существующие пути, а не описывать их по памяти.
2. **Уровень Gold не открывается.** Кремний Trinity — «отправлен на
   изготовление», измерительной цепочки нет. Значит tier `gold` в MVP
   объявляется зарезервированным и API обязан отвечать
   `422 tier_not_available`, а не ставить job в очередь. Иначе документация
   обещает то, чего нет.
3. **Silver ≠ доверие само по себе.** FPGA-исполнение даёт независимость только
   если реализация ядра НЕ производная от bronze-кода. Иначе это ускорение с
   тем же дефектом. Поле `independence_basis` (см. ниже) обязательно.
4. **Каталог форматов — 83.** Аппаратно закрытая часть — объединение осей
   примерно 49–55 из 83, не 71. Ядра `exact_numeric_kernel` объявляют
   `format_id` только из закрытого подмножества, остальное отвергается.
5. **Вердикты берутся из сита, а не из сервиса.** `SKIPPED_LOW_INFORMATION` —
   это решение ГЕЙТА (не запускать), а не вердикт утверждения. В API это
   разные поля: `gate_decision` и `verdict`. Смешивать их нельзя, иначе реестр
   начнёт копить отказы как находки.

## 1. Сущности

### JobSpec
```yaml
job_id:            uuid
job_type:          goldsieve_claim_batch | zeta_spacing_stats | zeta_bootstrap
                   | exact_numeric_kernel | paper_claim_audit
trust_tier:        bronze | silver          # gold зарезервирован
input_sha256:      hex
corpus_commit:     git sha
recipe_version:    semver сита (например 9.0.0)
recipe_fingerprint: hex                      # sha256 текста функций эталона
parameters:        {…}                       # схема на job_type
replay_policy:     none | bronze_then_silver | silver_twice
                   | bronze_silver_alternate_impl
visibility:        private | team | public
```
`recipe_fingerprint` считается сервером из присланного кода эталона и
возвращается пользователю ДО запуска — это машинный аналог пре-регистрации:
подкрутить терпимость после получения результата нельзя незаметно.

### GateDecision (до исполнения)
```yaml
admitted:        bool
U:               float          # max(U_precision,U_novelty,U_discrimination,U_independence)
U_min:           1.00
axes:            {precision: …, novelty: …, discrimination: …, independence: …}
status:          ADMITTED | SKIPPED_LOW_INFORMATION
novelty_key:     "corpus:<файл>:p<приоритет>" | "zeta:gap_shape:v1"
reference_case:  путь к репрезентативному прежнему кейсу того же класса
gate_fingerprint: hex          # настройки гейта, сейчас 9339d9009a65d7a1
```
Гейт стоит ПЕРЕД очередью: он экономит и кредиты, и реестр. Отказ обязан
ссылаться на прежний кейс — иначе это не отказ, а потеря.

### Verdict
`ПОДТВЕРЖДЕНО | ОПРОВЕРГНУТО | ВОПРОС | ПУСТО` + `reason_code` (сейчас 21
подтип, включая новые `control_broken` и `input_precision_limited`) + `action`.
Ни ПУСТО, ни ВОПРОС не публикуются как находка — в отчёте это отдельная секция
«не разрешено данными».

### EvidenceBundle
```yaml
inputs:            {path: sha256}
corpus_commit:     sha
tool_versions:     {python, numpy, scipy, mpmath}
recipe_fingerprint: hex
target_passport:   hex          # паспорт цели, см. Claim.target()
alpha, tolerance:  float
# только для silver:
board_idcode:      hex
bitstream_sha256:  hex
uart_transcript_sha256: hex
independence_basis: derived_from_bronze | alternate_impl | alternate_author
bronze_vs_silver:  {metric: (bronze, silver, rel_diff)}
```
`independence_basis = derived_from_bronze` — законное значение, но отчёт обязан
печатать его словами: «второй путь не независим, это ускорение».

### BoardAgent
Агент на хосте с AX7203: health/температура, загрузка ТОЛЬКО битстрима из
allowlist по sha256, исполнение пакета задания, снятие UART, подпись
свидетельства, эксклюзивная блокировка платы. Ни JTAG, ни USB, ни shell
пользователю не выдаются. UART — единственный настоящий свидетель, «синтез
прошёл» свидетельством не является.

## 2. Роли трёх плат

| плата | роль | что даёт |
|---|---|---|
| A | production | пропускная способность и SLA |
| B | independent replay, ДРУГАЯ реализация критического ядра | эпистемическая независимость |
| C | canary: новые ядра, квалификация | обновления без остановки сервиса |

Если все три несут один битстрим — это только скорость. Независимость требует,
чтобы хотя бы плата B держала альтернативную реализацию.

## 3. Порядок исполнения

1. `POST /jobs` → валидация схемы, вычисление `recipe_fingerprint`.
2. Гейт полезности → `SKIPPED_LOW_INFORMATION` (с ссылкой на прежний кейс) либо
   `ADMITTED`.
3. Bronze runner: CPU-эталон, полный каскад сит, отчёт + json.
4. Silver runner (если запрошен и ядро в allowlist): пакет задания на плату,
   сверка с bronze, `bronze_vs_silver`.
5. Сборка `EvidenceBundle`, запись в append-only ledger.
6. Отчёт: вердикт, подтип, действие, минимально различимое отклонение
   (`power`), провенанс.

## 4. MVP: Goldsieve Cloud, только bronze

Обоснование: логика аудита уже существует и проверена самопроверкой (135
проверок, 0 провалов на 2026-08-14), а FPGA-плечо не влияет ни на один вердикт
сегодняшнего каталога задач — узкое место в статистике, не в арифметике. Поэтому
FPGA добавляется как ускоритель второй фазой, а не как фундамент.

Фазы:
- Ф0 — заморозить JobSpec, GateDecision, EvidenceBundle как спеки в t27 (SSOT).
- Ф1 — bronze: приём заданий, реестр, отчёты, публичные ссылки.
- Ф2 — silver: агент AX7203, каталог битстримов по sha256, UART-свидетельство,
  сверка bronze/silver, `independence_basis`.
- Ф3 — аккаунты, квоты, расписания, экспорт приложения к статье.
- Ф4 — альтернативные реализации, политики перепрогона, разнообразие плат.

## 5. Что честно продаётся уже сейчас

- Машинный вердикт с провенансом и пре-регистрацией рецепта.
- Отрицательный результат как полноценный артефакт (два свежих примера:
  масштабная деформация с коэффициентом BBLM согласие не улучшает; форма
  распределения зазоров отклоняется от точного закона GUE, KS z = +6,3).
- Отказ от бесполезной проверки с объяснением (гейт полезности).

Что НЕ продаётся: «gold», кремний, «первый/единственный/лучший», покрытие всех
83 форматов аппаратно.
